### Changed
- **One JSON error shape across the API.** Unknown paths under `/api` and `/api/v1` now answer `{"error": "not found"}` as JSON, and a wrong method answers `{"error": "method not allowed"}` with an `Allow` header, where they used to be the plain text `404 page not found` and an empty `405`. A request body over the 1 MiB limit answers `413` with `{"error": "request body too large"}` instead of `400 invalid request body`; this applies to the indexer, download client, notification, import list, profile and custom format create and update calls, the genre calls and the manual import calls, and the remaining endpoints follow in a later change. A crash inside a handler is logged with its stack and a request id, so it shows up in Settings, Logs, and the client gets `{"error": "internal server error", "request_id": "..."}` rather than an empty `500`. The browser CSRF rejection and the OPDS Basic auth `429` and `503` are JSON now, and the CSRF one is labelled `application/json` (it was labelled `text/plain`). Lookups that failed because the database was unavailable used to say the row was not found: they now answer `500` instead of `404` for indexers, download clients, notifications, import lists, delay and metadata profiles, custom formats, the book file calls, history blocklisting, pending releases, genre apply and manual import. API change to note: `POST /api/v1/prowlarr/{id}/test` now returns `ok` as a JSON boolean (it was the string `"true"` or `"false"`), matching the indexer test. See the new Error format section in `docs/API.md`.
