### Changed
- **Bindery now deletes finished download rows after 90 days, and the queue, wanted list and download pollers no longer read everything on every request** (behaviour change): every grab adds a row to the downloads table and nothing ever removed one, so the queue page (polled every 5 seconds), the wanted list and each 15 second download poll all got slower the longer an install ran. A scheduled job now removes `imported` and `failed` rows more than `BINDERY_DOWNLOAD_RETENTION_DAYS` days old (default 90, set `0` to keep every row as before). The first pass runs six hours after you start the new version and removes every such row older than the window in one go, which on an install that has run for a year is most of the table, so set `BINDERY_DOWNLOAD_RETENTION_DAYS=0` before you first start the new version if you want to keep them. Rows that are still live or waiting for you (including `importFailed` and `importBlocked`) are never removed, and neither are History, the blocklist or your library. Plainly: once an imported row is gone, Bindery no longer remembers that exact release was grabbed, so if the book becomes wanted again (say you deleted its file) the same release can be grabbed again instead of being refused as already imported. The Queue page also stops listing an `imported` row after 7 days (older ones are on History), while failed and blocked rows stay until you deal with them. `GET /api/v1/wanted/missing` still returns the whole list as a bare array, but now also pages when you pass `limit` (answering `{items, total, limit, offset}`), which the Wanted page uses, and its search now runs on the server. The SABnzbd and NZBGet pollers look their downloads up once per poll instead of once per queue item.
