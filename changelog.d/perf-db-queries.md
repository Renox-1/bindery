### Changed
- **Faster book lookups on big libraries.** (#3185) Every book query used to build a table of the first file of each format across all book files before it answered, so opening one book cost the same as a whole library scan. Files are now looked up for the books on the page only. On a test library of 20,000 books and 30,000 files, opening a book went from about 54 ms to 0.13 ms, the first page of the Books list from about 66 ms to under 1 ms, a deep page (offset 10,000) from about 104 ms to 26 ms, and the Wanted list from about 98 ms to 20 ms.
- **History by event type no longer reads the whole table.** (#3185) A new index makes filtering History by event type (and counting those events) instant. On 200,000 history rows, the worst case went from about 220 ms to under 0.1 ms and the page count from 25 ms to under 2 ms. Three smaller indexes cover pending releases per book, the newest-first downloads list (about 295 ms to 261 ms for 50,000 rows with no limit) and the in use check when deleting a quality profile. They are built once at startup: about half a second on a library of that size.
- **Log writes are batched.** (#3185) The persistent log is now written in one transaction per 100 records or 250 ms, whichever comes first, instead of one write per line, so logging takes about 8 times less of the database connection's time (about 108 microseconds a record before, 14 after). After a crash or power loss the last 250 ms of log lines can be missing from the Logs page, and a normal shutdown writes everything out as before. A record that cannot be written is retried on its own and reported once on stderr.
- **Metadata cache eviction no longer scans the whole cache.** (#3185) When the in memory metadata cache is full, making room now looks at a sample of 32 entries rather than every entry while holding the cache lock, so a lookup no longer waits behind a scan of thousands of entries (about 140 microseconds at the 10,000 entry cap before, under 1 after).
