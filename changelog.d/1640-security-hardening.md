### Security
- **File deletes refuse paths outside every library root, including when no root is configured.** Deleting a book or an author with its files now checks that each file sits inside a root folder (or `BINDERY_LIBRARY_DIR` / `BINDERY_AUDIOBOOK_DIR`). Before, the check let everything through when no root resolved at all. A normal install always has `/books` or your own library folder, so nothing changes there. The refusal is logged with the path, and the row is still removed.
- **A symlink inside a library root that points outside it is no longer deletable.** The delete check used to accept the path as written even when it resolved somewhere else. Both the path and the root are now resolved, so a library root that is itself a symlink to another volume keeps working, and a file that is already gone can still be cleaned up.
- **The outbound proxy no longer skips the connect time address check.** With `BINDERY_OUTBOUND_PROXY` set, a destination on the bypass list (`BINDERY_OUTBOUND_PROXY_BYPASS_LOCAL` or `BINDERY_OUTBOUND_PROXY_NO_PROXY`) was dialled directly with no check on the address it resolved to. Cover images, webhooks, Prowlarr and OIDC discovery now check those direct connections too. Your own proxy is still reachable on a LAN or loopback address.
- **Download clients and Audiobookshelf can no longer redirect Bindery to a link local or cloud metadata address.** Connections to SABnzbd, NZBGet, qBittorrent, Deluge, Transmission, rTorrent and Audiobookshelf are checked when they connect and on every redirect. LAN, loopback and Docker hostnames work as before, and these clients still do not use `BINDERY_OUTBOUND_PROXY`. A client saved on a `169.254.x.x` address now fails with a clear "link-local address" error.
- **Changing your password is rate limited.** Six wrong current passwords in a row now return 429, the same as the login form, so a stolen session cookie cannot be used to guess the password. A successful change clears the count.
- **The public OIDC provider list no longer shows discovery errors or group names.** `GET /api/v1/auth/oidc/providers` still gives the login page what it needs, but `last_error`, `last_attempt` and `allowed_groups` are only returned to an admin.
- **`GET /api/v1/auth/oidc/redirect-base` is admin only, and forwarded headers are validated** (#1640). The endpoint now needs an admin. `X-Forwarded-Proto` must be `http` or `https`, and `X-Forwarded-Host` must be a plain host with an optional port, before either is used to build the OIDC redirect URL. Anything else is ignored and the request's own Host is used.
- **Stored password hashes with extreme argon2 settings are refused.** A hash asking for more than 256 MiB, 10 passes or 8 threads is rejected before any work is done, and one with zero passes or threads can no longer crash the login. Hashes written by Bindery are unaffected.
- **Calibre and Readarr database paths with `?`, `#` or `%` in them are opened literally.** The path was pasted into the database connection string, so a folder name such as `lib ?mode=rwc` could change how, and which, file was opened.
